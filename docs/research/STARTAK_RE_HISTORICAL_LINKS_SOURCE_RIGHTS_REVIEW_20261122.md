# ستارتك العقارية — استرجاع الروابط السابقة وفحص المصدر وحقوق البيانات

**تاريخ البحث:** 2026-11-22، توقيت الرياض. **نطاق المشروع:** `turkialeid2030/startak-real-estate`. **مستوى الإثبات:** روابط سبق أن أوردها المستخدم + الصفحات العامة المتاحة + فحص شفرة وسجلات STARTAK. **ليس** اعتمادًا نظاميًا أو تقييمًا مهنيًا أو فحص API مؤسسيًا.

## 1. طريقة الاسترجاع وحدود المعرفة

- استُعيدت الروابط التي قدمها المستخدم في جلسة **30 سبتمبر 2026** بشأن Earth وSuhail وTathmin والصفقات والخرائط والبوابات الرسمية، وفي جلسة **8 أكتوبر 2026** بشأن طرق التقييم وشركات التقييم والتدريب، ثم رابط `https://umaps.momah.gov.sa/` في **22 نوفمبر 2026**. ترد بعض الروابط قديمًا كاسم نطاق لا كعنوان مقال محدد؛ لذلك لا يُختلق مسار مقال.
- المصادر المضافة في سجل النسخ الحديثة (Kite/Paseetah/GREM وغيرها) موثقة أدناه في قسم **إضافات من المشروع**؛ **لا ننسب إرسالها في تلك الجلستين إلى المستخدم دون سند**.
- فحص الويب هنا يعني القدرة على قراءة وصف عام أو صفحة. الواجهات التي تتطلب JavaScript أو جلسة هوية أو لم تستجب لا تثبت فشل الموقع للمستخدم ولا وجود API.
- لا تجمع هذه المراجعة سجلات صفقات حقيقية أو أسماء ملاك أو حسابات أو وثائق صكوك. الشفرة والتقارير في STARTAK تظل `HOLD_NOT_AUTHORIZED` للإطلاق المهني والتجاري.

## 5. مصفوفة التمييز بين السلطة المصدرية والبيانات التجارية

1. **المصدر الأولي للصفقة/العقد:** سجل موثق أو مجموعة بيانات حكومية محددة بترخيص قابل للمراجعة. رقم الصفقة وتاريخها والموقع ونوع العقار والحق والمساحة ووحدة القياس إلزامية لكل مقارنة قابلة للاختبار.
2. **المجمع/المؤشر الرسمي:** REGA أو GASTAT يوفر الاتجاه والنطاق الإحصائي؛ لا يُنزّل ضمنيًا إلى قيمة منفردة.
3. **المصدر البلدي/الجغرافي:** UMAPS وبلدي وجيومكانية؛ طبقة الاستعمال والاشتراطات والحدود لا تثبت ملكية الصك أو القيمة السوقية.
4. **الإعلان:** طلب/عرض قائم في راكز وجذان وأرض وبيوت؛ يجب `ASKING` ولا يدخل سوق المقارنات المنفذة تلقائيًا.
5. **التقدير الخارجي AVM:** سهيل/بسيطة/GREM/بيوت وتثمين إن ثبت عمله؛ يعرض مقارنة أو تحديًا للنموذج، لا `EXECUTED` ولا رأيًا مهنيًا.
6. **التقرير المهني:** المرجع هو رأي مقيم مرخص وموقع ضمن نطاق عمل مؤرخ، مع توثيق المصدر والمنهجية؛ لا تُرفع درجة الثقة من صفحة شركة ترويجية.

## 6. ما ينبغي تنفيذه داخل ستارتك — معايير قبول قابلة للتدقيق

**P0: عقد المصدر وحق الاستعمال.** إنشاء `SourceAgreementRegister` لكل أصل بيانات لا لكل نطاق فقط: `sourceId, datasetId, authority, exactUrl, rightsHolder, licenseVersion, commercialUse, derivativeUse, bulkAccess, personalData, attribution, retention, redistribution, permissionEvidenceId, checkedAt, expiresAt`. حالة غير مثبتة `NO_PRODUCTION_INGEST`. لا يستنتج النظام أن ترخيص بيانات وزارة العدل المفتوحة يسمح باستخراج محتويات واجهة REGA المقيدة.

**P0: هوية الصفقة.** تخزين `originalIssuer, originalRecordId, providerRecordId, recordKind(ASKING/EXECUTED/INDEX/AVM), city, district, parcel/plan(if authorized), assetClass, valuationInterest, areaBasis, areaSqm, amountSar, rentPeriod, transactionDate, publicationDate, snapshotDate, originalSourceUrl, licenceId, qualityFlags`. تفريق تاريخ العقد عن تاريخ تحديث الصفحة، ومساحة الأرض عن البناء وNLA/GLA، وتصنيف «سكني» عن نوع المبنى القائم.

**P0: اكتشاف الازدواج/النزاع.** إذا ظهرت الصفقة الحكومية نفسها في Kite وEarth وREGA، لا تعد ثلاث مشاهدات مستقلة. تتبع `originId` والتاريخ والعقار والمصدر الأصلي. الأسعار المتضاربة/حقوق مختلفة/تصنيف مختلف => HOLD؛ لا متوسط صامت.

**P0: دمج جغرافي آمن.** UMAPS مصدر مراجعة استعمال/مخطط/اشتراطات فقط مع `sourceObservedAt, parcelKey, verifier, validityWindow`. بداية الإدخال اليدوي `UNVERIFIED`؛ لا تقرر ملكية أو FAR أو ارتدادات نهائية حتى تحقق مصدر مخول ومراجع. لا استخراج آلي من بوابة دخول بلا عقد.

**P0: التجارب المرجعية.** تشغيل 17+4 حالة خاصة من مصدر مخول على محرك STARTAK الحقيقي وحفظ/استرجاع/تقرير باللغة العربية والإنجليزية، ثم فصل عينة صفقات سعودية مستقلة لحساب MAE/MAPE والتغطية وفترات الثقة، وإجراء تحدي خارجي مع AVM/مقيم مستقل دون إعادة استخدام نفس مصدر التسمية كـ«اختبار مستقل».

**P1: شراكات تجريبية بدل الكشط.** فحص شروط Kite (تغطية وجودة/API/حماية حقوق)، ثم GREM/Paseetah وSuhail/Earth بعقود وحق استخدام واضح. ينبغي تسجيل `NO_API_VERIFIED` لكل واجهة غير موثقة رسميًا أو تعاقديًا.

**P1: نموذج التقييم المهني.** إثراء قائمة فحص تقرير التقييم بمعايير Taqeem/IVS: التكليف، الغرض، المستخدم المقصود، الحق، تاريخ القيمة، معاينة، وصف، HBU، أدلة الصفقات/الإيجار، أسلوب السوق/الدخل/التكلفة، المصالحة، الافتراضات، الحدود، توقيع المقيم والملف القابل للتدقيق.

**P1: مقارنة عروض السوق.** تعرض الأسعار المطلوبة بعلامة `ASKING`، وتستخدم لضغط السعر والمدة المعروضة وسيولة السوق ولا تنشئ مبيعات «منفذة» اصطناعًا. المدخلات الهندسية من Building Rank تُعزل عن مدخل القيمة ولا تُستخدم إلا بعد تقرير مختص.

## 7. الخلاصة التنفيذية / قرار النشر

- المصدر الوحيد الذي ثبت من هذه الجولة أنه يعرض **واجهة API موثقة علنًا** في المجموعة الإضافية هو Kite؛ وGREM **يعلن** إتاحة API تجارية لكنه لم يُختبر بمفتاح/عقد. هذا لا يمنح STARTAK حق استخدامهما الإنتاجي تلقائيًا.
- مسار UMAPS المنفذ في مسودة [PR #815](https://github.com/turkialeid2030/startak-real-estate/pull/815) يضيف رابطًا يدويًا ومجالًا رسميًا إلى C1 فقط. تبقى `productionAdapterEnabled=false`.
- **REGA terms:** لا تعاد صياغتها على أنها رخصة بيانات مفتوحة؛ يلزم إذن مكتوب لإعادة استعمال محتوى واجهة المؤشرات، أو الاعتماد على مجموعة بيانات منفصلة منشورة برخصة صريحة وفحص نطاق تلك الرخصة.
- أي دقة مقدرة أو عدد معاملات من صفحات الشركات يمكن أن يكون تسويقًا أو إحصاءات مجمعة؛ لا تُمنح شهادة دقة آلية لستارتك.
- **القرار:** البحث/التوثيق `GO`، تطوير التحقق والاختبارات الاصطناعية `GO`، الاستيعاب الآلي للبيانات وإصدار قيمة مهنية أو إطلاق تجاري `HOLD_NOT_AUTHORIZED` حتى الأدلة المستقلة والحقوق والاعتمادات والتجارب الحقيقية.
