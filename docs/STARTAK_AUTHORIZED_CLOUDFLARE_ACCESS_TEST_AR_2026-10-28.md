# STARTAK — تشغيل فحص Cloudflare Access المخوّل (أكتوبر 2026)

**القرار الحالي:** `HOLD / NOT_AUTHORIZED` للتقييم المهني والتوصية الاستثمارية والإطلاق التجاري. هذه التعليمات لفحص معاينة شخصية محمية، لا لإنشاء موافقة نشر.

## ما أثبته الفحص

- المعاينة المحددة: `https://1647dc09.startak-real-estate.pages.dev/`.
- تحقق GitHub Actions من DNS واستجابة **HTTP 302** لـ `/` و`/release-manifest.json` و`/asset-manifest.json`، تتحول إلى `startak-real-estate-pages.cloudflareaccess.com`.
- دخول البريد ورمز OTP مطلوب للمستخدمين. لا يجوز اختصار هذه الحماية أو تعميم أسرار الدخول.
- نجاح بناء Cloudflare Pages لا يعادل نجاح تنزيل الأصول بعد الدخول، ولا يثبت دقة القيمة السوقية.

## المسار الأول — التجربة البشرية في ChatGPT Work

1. افتح Work في ChatGPT بمتصفح سحابي، وافتح الرابط أعلاه.
2. أدخل البريد المصرح له في صفحة Cloudflare Access وأدخل رمز OTP **داخل الموقع فقط**، لا في المحادثة.
3. بعد التأكد من ظهور التطبيق نفسه بدل صفحة الدخول، نفذ سيناريو تجربة ببيانات اصطناعية/مسموح استخدامها: اختيار فئة عقار ومدينة/حي، إدخال المساحات والإيجارات والأسعار المطلوبة والصفقات المبلّغ عنها، حفظ واستعادة الملف، مقارنة المناهج، مراجعة قائمة العوائق، وتنزيل التقريرين JSON/HTML.
4. احفظ نتيجة كل اختبار: الشاشة/التاريخ/نسخة البناء، المدخلات، النتيجة المتوقعة والمشاهدة، الخطأ، وإجراء الإصلاح. لا تعرض بيانات العملاء في سجل عام.

جلسة Work البشرية **لا تُنقل** إلى GitHub Actions.

## المسار الثاني — فحص آلي مؤسسي مصرح به

أُعد على فرع PR #764:
- `tools/verify-protected-preview.mjs`؛ يضيف ترويستي `CF-Access-Client-Id` و`CF-Access-Client-Secret` **لنفس نطاق المعاينة المسموح فقط**، ويمنع إعادة التوجيه، ثم يتحقق من Manifest SHA، وأحجام الأصول وبصمات SHA-256 و404. لا يصدر إذنًا شرعيًا أو اعتمادًا تجاريًا.
- `tests/architecture/run_protected_preview_access.js`؛ اختبارات تركيبية بلا أي رمز حقيقي، وتشمل رفض الروابط الأخرى، تسريب الترويسات عبر نطاقات مختلفة، ورفض 302.
- `.github/workflows/authenticated-preview-delivery-manual.yml`؛ تشغيل يدوي على **main فقط**، لا على PR أو رأس فرع غير مراجع، ويستخدم بيئة أسرار مستقلة.

### إعدادات مسؤول النظام المطلوبة قبل التشغيل

1. في **Cloudflare Zero Trust**، أنشئ **Service Token** مخصصًا وقصير الصلاحية لمعاينة STARTAK، ثم أضف سياسة **Service Auth** لـAccess Application الخاصة بالمعاينة فقط. لا تعطّل تسجيل البريد وOTP للمستخدمين.
2. في GitHub `Settings > Environments` أنشئ بيئة `startak-preview-audit`، وحدد `Selected branches: main` ومراجعًا مفوضًا للموافقة على تشغيلها.
3. ضع الترويستين في **Environment secrets** فقط: `STARTAK_CF_ACCESS_CLIENT_ID` و`STARTAK_CF_ACCESS_CLIENT_SECRET`. لا ترفعهما إلى الملفات، ولا تشاركهما هنا.
4. **بعد مراجعة الكود ودمج سير العمل المعتمد في main**، شغّل `Authorized Cloudflare Preview Delivery Audit` يدويًا من Actions. حدّد رابط المعاينة والبصمة SHA المطلوبة، وأكمل مراجعة الموافقة على البيئة.
5. إذا فشل الفحص، راجع كود الفشل من دون طباعة الأسرار. نجاح الفحص يثبت فقط تطابق التسليم على ذلك الرابط والبصمة في وقت الرصد؛ لا يثبت قيمة العقار أو ملاءة المستأجر أو اعتماد التقييم.

**قيد أمن حاكم:** لا تمنح `pull_request` أو `pull_request_target` إمكانية الوصول إلى أسرار الخدمة؛ لا تشغّل هذه الأسرار على كود غير مراجع. إعداد البيئة نفسه إجراء إداري لم ينفذ من داخل ChatGPT، كما لم تنشأ Service Token فعلية أو سياسة Service Auth أو جلسة OTP فعلية.

## شروط نجاح مجلس تركي الاستشاري

- واجهات وأزرار وإدخال وحفظ وتقرير: `PASS` فقط بدليل من المتصفح المخول على نسخة معروفة البصمة.
- المعادلات: `PASS` بعد Golden Cases مستقلة للـNOI/IRR/NPV/التمويل وتكاليف الاستحواذ، ثم مطابقة عقود ودفاتر حقيقية بحق استخدامها.
- الصفقات السعودية والحقوق: `NOT VERIFIED` حتى ثبوت المصدر الفردي وصفقة منفذة مستقلة وصك/قطعة ومطابقة التاريخ ونوع الأصل.
- دقة AI: `NOT VALIDATED` حتى قياس خارج عينة التدريب من معاملات سعودية موثقة مع MAPE/MAE وتجزئة زمنية وجغرافية وقطاعية؛ لا تفويض تلقائي بالشراء.
- حقوق البيانات/PDPL، أمن IdP/KMS/RBAC، والتوقيع المهني وقبول Q01–Q12: تبقى **OPEN** حتى أدلتها الحقيقية.

**مراجع رسمية:** وثائق Cloudflare Access Service Tokens، وGitHub Actions Environments & Required Reviewers. استلام الرمز أو اعتماد التشغيل يتطلب صاحبه المخوّل.
